# Clean-room rules

CrewCraft is written from scratch, and it is developed in the open. These rules keep it an independent codebase and free of anything private.

CrewCraft also follows the Craft clean-room standard,
[`standards/clean-room.md`](https://github.com/storytold/craft-contrib/blob/main/standards/clean-room.md) in
storytold/craft-contrib. Rules 5 to 9 restate its MUST rules so they hold here in full; where this file and the standard
differ, the stricter rule applies.

1. **CrewCraft is written from its own written requirements.** It is built from scratch from [REQUIREMENTS.md](REQUIREMENTS.md) and [SPEC.md](SPEC.md); no code, schema, strings or assets are copied from other products.
2. **No copying.** No file, snippet, schema, test, string or asset from another product's implementation. Implementing a behaviour that REQUIREMENTS.md describes is the point; transcribing someone else's implementation is not.
3. **Open-source dependencies are fine** under licenses compatible with MIT OR Apache-2.0 (checked by `cargo deny`
   once dependencies grow). Libraries such as egui (and forks of it) and ArtCraft's craft-libs (https://github.com/storytold/craft-libs) would be acceptable dependencies.
   **Fonts** may be under the SIL Open Font License 1.1 (`OFL-1.1`). The font stays under the OFL. Its license text
   ships next to the font file in the repo and in every release, and a modified font may not keep a Reserved Font Name.
   No other font license is approved. egui's `default_fonts` feature pulls in `Ubuntu-font-1.0`, so the client turns
   that feature off and bundles its own OFL font.
4. **Nothing private, ever.** No hostnames, domains, IP addresses, people's names, customer names, email addresses
   other than `example.org`/`example.com`, credentials, keys, certificate fingerprints, or names of internal systems.
   `tools/sanitize-scan.sh` enforces a pattern list in the gate; the release gate adds human review.
5. **Learn only from public sources:** published specifications and conformance material; public documentation (help
   pages, published screenshots, tutorial videos); papers and textbooks; and behaviour specifications written as rule 8
   describes. Learn behaviour and ideas, never code. Cite the source in the module or crate docs, and for a protocol or
   file format name the specification and its edition (for example, `apps/crewcraft-server/src/import_teams.rs` names
   the public API documentation it was built from). Saying that code is clean-room is not evidence of it.
6. **No remembered internals.** Do not use remembered knowledge of a proprietary product's internals: SDK class names,
   identifiers, storage or wire details. A fact that no public specification, behaviour specification or published
   sample shows does not go in.
7. **Never read copyleft code.** Do not read, copy or link GPL, LGPL or AGPL code. A copyleft tool may run as a separate
   process that generates fixtures or checks output in a test; CrewCraft's own code never links or bundles one. The one
   copyleft part in a release is recorded in [ATTRIBUTION.md](../ATTRIBUTION.md): the prebuilt, unmodified AppImage
   runtime at the front of the Linux AppImage, which links libfuse (LGPL-2.1) and ships with its licences and where to
   get its source, as the Craft apps' AppImages do.
8. **Observing another product takes two roles, never one session.**
   - The **observer** operates the product, only with inputs we made or a contributor owns. It writes only a
     behaviour specification: what a user sees and does. It screenshots only the product's window. It never
     instruments the product (no tracing, debugging, memory or traffic inspection), and never reads, disassembles or
     copies anything inside its install.
   - The **implementer** writes code from behaviour specifications, public documentation and published
     specifications. It never operates the product or reads its install.
   - Screenshots, recordings and observation notes stay out of the repository, issues and pull requests.
9. **Every asset and fixture has a recorded origin, in the same change.**
   - An asset (icon, image, font, sound, theme, sample data, bytes embedded in code) is original work by a contributor,
     or comes under a license on the Craft allowlist from its original source, at an exact version.
   - A fixture (a file tests read) is generated by a committed script from our own inputs, or was published by others
     for their own purposes and is taken from its original source under such a license.
   - Each gets a row in [ATTRIBUTION.md](../ATTRIBUTION.md): path, author, source and version, license, and how it was
     obtained or made.
   - Nothing comes from another product, its installer, website or documents: no icons, artwork, fonts it installs,
     sounds, templates or sample files, and no traced, redrawn or recoloured copies, even as placeholders.
